# VERIFIED TOOL REGISTRY — как я вижу развитие

**Дата:** 20.10.2026 · **Автор:** IndrA

## 0. Коротко (одна строка)
**skilllint проверяет скилл → attest подписывает вердикт → drift разрешает или запрещает вызов.**
Это «поставка с проверкой» для агентских площадок. Отдельный продукт **не нужен**: это связка наших трёх существующих продуктов, оформленная как отдельная стратегия продвижения.

## 1. Почему НЕ отдельный репозиторий и НЕ копия SkillSpector
| Факт | Следствие |
|---|---|
| F-01…F-03: NVIDIA SkillSpector — 71 паттерн, AST, YARA, CVE, MCP, CI, SARIF, Apache-2.0 | Строить второй сканер бессмысленно (I-01) |
| F-04: сканеры отправляют содержимое проверяемого артефакта наружу | Наша ниша — **приватность**: проверка локально, наружу только хеш и вердикт (I-02) |
| F-07: все инструменты сканируют один артефакт за вызов | Ниша — **сравнение кандидатов** из нескольких реестров (I-03) |
| I-04: продукт, проверяющий сам себя, хрупок (жёсткая привязка к версии) | Наш продукт **не проверяет себя** — он проверяет *чужие* артефакты |
| I-05: платный слой должен быть сетевым по построению | Деньги — в слоях, которые **невозможно сделать локально**: сравнение реестров, история вердиктов, командные политики |

## 2. Три слоя, каждый со своей ценностью

| Слой | Что делает | Приватность | Платный? |
|---|---|---|---|
| **1. Линтер** (`skilllint`) | структура, триггеры, секреты, инъекции, битые ссылки, автономия; вердикт + sha256 | полная (локально) | нет — это приманка и доверие |
| **2. Подпись** (`attest`) | хеш+вердикт → подписанный receipt, проверяется офлайн, без доверия к нам | наружу — только хеш | да (per-signature / подписка) |
| **3. Реестр и политики** (`drift` + сеть) | allowlist «можно подключать этот скилл», лимиты, kill-switch, история вердиктов, сравнение кандидатов из N реестров | сеть (то, что нельзя сделать офлайн) | да (командные политики) |

**Правило продажи:** бесплатно — то, что можно сделать локально; платно — то, что по построению требует сети (I-05).

## 3. Поток (без изменения исходников)
```
SKILL.md ──► skilllint.lint_skill()  ──► {verdict, score, sha256}
                    │
                    ├─► attest /verify  ──► signed receipt (офлайн-проверяемый)
                    └─► drift: allowlist / мандат «подключать только проверенное»
```
`skilllint` и `attest` **не знают** друг о друге: связь делает вызывающий (Suite или агент).
Это и есть «не ломая исходники»: ни одна строка в `attest`/`drift`/`agentpay` не меняется.

## 4. Отдельная стратегия продвижения (без нового продукта)
1. **Позиционирование:** «SkillSpector сканирует один артефакт и отправляет его содержимое наружу. Мы проверяем локально, подписываем вердикт и даём сети доверять именно этому скиллу».
2. **Доказательная база:** наш `docs/EVIDENCE.md` — публикуется как есть (FACT/INFERENCE/HYPOTHESIS). Это то, чего нет ни у кого: **приватность + воспроизводимость + сравнение**.
3. **Каналы:** GitHub (репозиторий + issue-шаблон «проверь мой скилл»), статья (dev.to/HN) про supply-chain атак на скиллы, MCP-каталоги (`skilllint` MCP уже готов), партнёрство с агентскими площадками (они получают «проверенный» знак для своих витрин).
4. **Бесплатный трафик-механизм:** проверяй чужой скилл бесплатно → покажи вердикт со ссылкой на подпись → владелец скилла приводит своих пользователей. Loop: проверка → репутация → установка.
5. **Монетизация:** $0.002–0.01 за подпись вердикта; командная подписка (allowlist + история) $19–49/мес за команду; enterprise (SLA, on-prem, политики) — отдельно.
6. **Проверка спроса (без кода):** 10 офферов «проверю ваш скилл бесплатно» + landing с формой; цель — 3 согласия платить.

## 6. Границы и честность
- U-04 (команды платят за приватную проверку) — **HYPOTHESIS**, не факт. Первые платящие = главный риск.
- Мы не заменяем SkillSpector: он остаётся лучшим сканером; наша надстройка — приватность, подпись, реестр, политики.
- Вердикты skilllint — правила нашего линтера, не аудит безопасности; для глубокого аудита — SkillSpector.
- Публичный реестр скиллов с подписью требует сервера и денег на инфраструктуру (пока — локально + подпись attest).
